# Build round 1: deviations, contract issues and follow-ups

Reported by the seven build-round-1 work packages. Items marked as Mac verification must be checked on real macOS hardware (see also spikes/README.md).

## input-policy

### deviations
- keys.parse_combo: an uppercase ASCII letter adds `shift` only when no cmd/ctrl/option/fn is held ("T" -> shift+t, "⌘⇧T" -> cmd+shift+t), but "Cmd+C"/"⌘C" -> cmd+c. The contract says uppercase always adds shift. Rationale: macOS menu notation (and MenuNode.shortcut strings like "⌘C") show uppercase letters without shift, and models often write "Cmd+Q"/"Cmd+W"/"Cmd+V"; under the strict rule these would become Log Out / Close All / Paste and Match Style. Reverting is a one-line change in _build_combo.
- keys.parse_combo: modifier-only input ("shift", "fn", "cmd+shift") is accepted and taps the last modifier written (KeyCombo("shift", {"cmd"})) instead of raising. Modifier names are therefore in KEY_NAMES and US_ANSI_KEYCODES.
- keys: a trailing "^" is the caret key ("cmd+^"); anywhere else "^" is ctrl as the contract says. The literal +/- keys are written doubled, after a glyph or by name; a dangling "cmd+" raises INVALID_ARGUMENT with a hint.
- keys: canonical names chosen where the contract left them open: volume_up, volume_down, mute, plus extra named keys help, eisu, kana and keypad_0..9/keypad_*. Additive exports: KEY_ALIASES, MODIFIER_ALIASES, US_ANSI_SHIFTED, ansi_keycode(key) -> (keycode, needs_shift), modifier_mask(mods), to_glyphs(combo), MAX_COMBO_LENGTH, MAX_SEQUENCE_LENGTH.
- coords: additionally exports CoordinateSpace / COORDINATE_SPACES. Screenshot pixels outside [0,width]x[0,height] and non-finite values raise INVALID_ARGUMENT.
- profiles: additive ALL_TOOLS, DEFAULT_PROFILE, expand_names(). disable is applied after enable (a name in both ends up disabled). Names are matched after strip/casefold.
- rules: extra safety rules beyond the contract. AXPilot's own app (bundle id or name 'AXPilot') is always observable/capturable even if denied or not allowed, but input into it is always BLOCKED_BY_POLICY (rule 'self'), so an agent cannot approve its own confirmations. Input into com.apple.SecurityAgent raises NEEDS_USER.
- rules: app entries support `*` wildcards; names match with or without '.app'. A deny_windows entry without '::' applies to every app; an empty title part raises INVALID_ARGUMENT at construction. With allow_apps set, input to an unidentified target (app=None) is blocked. is_terminal also matches by app name.
- rules: requires_confirmation in 'destructive' mode also returns True for shell/applescript/browser_eval_js even when destructive=False; 'always' mode exempts only the read-only observe toolset.
- rules: additive API: capture_exclusions(running_apps=None) (with running apps it resolves name/wildcard entries and excludes non-allowed apps), check_tool(tool) raising TOOL_DISABLED, is_self(app), shell_enabled, CONFIRM_BY_DEFAULT_TOOLS, TERMINAL_APP_NAMES, AUTH_DIALOG_BUNDLE_IDS.
- ratelimit: additive keyword window_s (default 60) plus remaining() and reset(). A call at exactly t+60 s is allowed again.
- audit: additive keyword args max_bytes (default 10 MB, rotation to <name>.1; tail spans both files), memory_size, and clock; plus entry(), backup_path, REDACTED_KEYS, LOG_ARG_MODES. Mode 'none' writes "args": {}. Bytes are logged as "<N bytes>" in every mode. The redaction marker keeps the contract text literally ("<redacted 1 chars>").
- confirm: additive ensure_confirmed(confirmer, request) raising USER_DENIED; AutoConfirmer.requests records requests; DenyConfirmer.denial_hint explains --yes / confirm='never'.
- control: input_turn has an extra keyword-only `label`. pause() also cancels the input turn in progress, from any thread; that turn raises PAUSED_BY_USER. Additive ensure_running(), busy, current_action, to_dict(). Opening a nested turn in the same task raises INTERNAL instead of deadlocking. If hid_idle_seconds() raises a non-AXPilotError, the turn fails with INTERNAL (fail closed).

### contract_issues
- pyproject.toml allows anyio>=4.9, but cancelling an in-flight turn from another thread uses anyio.lowlevel.current_token(), added in anyio 4.11. control.py degrades gracefully: on older anyio, a pause from another thread still blocks new turns but cannot interrupt a running one. Recommend bumping to anyio>=4.11 (the lock pins 4.15).
- CONTRACTS.md section 3 says an uppercase letter always adds shift. This conflicts with Apple menu notation, where "⌘C" means cmd+c. Recommend updating the contract to the implemented rule (implicit shift only without cmd/ctrl/option/fn), or deciding otherwise and telling me.
- PLAN 7.2 says terminal input unlocks when `scripting` is enabled; CONTRACTS.md says when `shell` is enabled. Implemented per the contract (shell tool); the two documents should agree.
- Policy.requires_confirmation(tool, destructive) has no read_only information, so confirm='always' can only exempt the observe toolset. Read-only actions of other tools (clipboard read, processes list, system_info, shortcuts list) will still ask. Consider adding a read_only flag to the contract.
- The config field is SafetyConfig.user_idle_threshold_s, while ControlState takes idle_threshold_s. ServerContext.create must map one to the other. Not a bug, but worth stating in CONTRACTS.md section 6.
- CONTRACTS.md should list the additive APIs other modules will want: input_turn(timeout_s, *, label=None), Policy.capture_exclusions(running_apps=None), Policy.check_tool(), ensure_confirmed(), ControlState.ensure_running()/to_dict(), keys.ansi_keycode()/modifier_mask()/to_glyphs().

### followups
- Server guard: pass the window title to Policy.check_app so deny_windows can take effect; pass engine.list_apps() to capture_exclusions(); use input_turn(label=tool_name); use ensure_confirmed(); call control.ensure_running() between sub-steps of long actions (fill_form, chunked type_text, drags).
- Server/context: build Policy with enabled_tools(config.tools.profile, config.tools.enable, config.tools.disable); RateLimiter(config.safety.max_actions_per_minute); AuditLog(config.audit_path(), enabled=config.audit.enabled, log_args=config.audit.log_args); ControlState(engine, yield_to_user=config.safety.yield_to_user, idle_threshold_s=config.safety.user_idle_threshold_s).
- Host: wire the kill-switch hotkey and the menu-bar Stop item to control.pause("kill switch"). It is safe to call from the AppKit main thread and never blocks on the event loop.
- Engine (macOS): resolve KeyCombo keys through the current layout via UCKeyTranslate, falling back to keys.ansi_keycode() and keys.modifier_mask(). Posting kVK_VolumeUp/Down/Mute as CGEvent key codes may not change the volume on real hardware; NX system-defined media-key events may be needed.
- Bump the anyio floor in pyproject.toml to >=4.11 (owner of pyproject).

## perception

### deviations
- SnapshotDiff: I appended five optional fields, all defaulting to None: app_before, app_after, window_before, window_after and focus_after_ref. They let format_diff print 'app: A → B', 'window: "X" → "Y"' and 'focus: "Body" → e1 "Search"'. Positional construction of the contract fields is unchanged.
- Interactive pruning, extras on top of the contract: (a) sheets, popovers and dialogs are kept even when unnamed, and static text inside them is kept, because that is where alert messages are; (b) the root window or application element is not listed (the header covers it); (c) the close/minimize/zoom/full-screen buttons are omitted (the window tool covers them); (d) AXMenuBar subtrees are excluded (the menus line covers them); (e) named AXGroup/AXRadioGroup/AXPopover count as context roles.
- Zero-size and outside-the-window nodes skip only themselves; their children are still checked one by one (web content often nests visible nodes in 0×0 wrappers). The contract only says 'and their subtrees' explicitly for visible=False. Nodes inside an open AXMenu are exempt from the window-bounds check because menus float outside the window.
- Name fallbacks after placeholder: static text uses its value as the name (its value field is then None, to avoid repeating it); unnamed interactive elements and headings take up to two descendant static texts joined by ' — ' (this is how a Notes row gets the name 'Shopping list — 10:42'); window-frame buttons get fixed labels (Close/Minimize/Zoom/Full Screen).
- "Focusable text role" in is_interactive is read as a text role (AXTextField/AXTextArea/AXComboBox/AXStaticText/AXWebArea) that currently has focused=True, because RawNode has no focusable attribute.
- Checkbox, switch, radio and tab values are shown as the state words 'checked'/'mixed' instead of value="1" (Element.value still holds "1"). Element has extra properties center, identifier, checked and states; Snapshot has total, next_offset, element(ref) and focused_element.
- Text format specifics: coordinates are shown only for interactive elements; values are cut to 80 characters in text (the JSON keeps the snapshot's full value); the header says 'no window' when there is none; the footer adds ', offset N' for later pages, a hint when nothing is actionable, and a note when the capture was truncated. 'total' in both the footer and the payload is len(all_elements), not total_nodes.
- diff_snapshots matches in five passes: identifier → locator path with the same name → (ax_role, name, rounded frame) → (ax_role, name) when unique on both sides → path alone when the frames overlap. When the app or window differs, nothing is matched, and format_diff collapses the removed elements into one line ('- N elements of the previous window').
- match_locator (used by live_handle) tries identifier (ties broken by path, then name), then path only if the node there has the same role and name (or the element was unnamed), then a unique role+name match. It deliberately has no 'path regardless of name' fallback, so a stale ref can never act on a different control that now occupies the same position.
- SnapshotStore.resolve raises STALE_REF when the ref is well-formed but not in the snapshot, and INVALID_ARGUMENT for malformed refs or a snapshot_id that conflicts with the one in the ref. Additions: parse_ref(), IdFactory, clear(), __len__ and __contains__. Ids are 's_' plus 4 base-36 characters.
- FakeEngine test hooks, since the contract doesn't name them: settable attributes hid_idle (returned by hid_idle_seconds(), default 999), secure_input (returned by secure_input_active()), permission_status (a PermissionStatus) and clipboard (a ClipboardContent); helper methods set_permissions(), resolve_ref(fixture_id_or_identifier) → current handle, secure_value(handle), events_of(kind); attribute scroll_offsets.
- FakeEngine behaviour beyond the contract: type_text and press_key raise SECURE_INPUT_ACTIVE while secure_input is True; tree, action, input, menu and window methods raise PERMISSION_ACCESSIBILITY when accessibility is off; screenshot raises PERMISSION_SCREEN_RECORDING. Pressing an element logs ('press', {handle, name}) after the primary event. screenshot is logged as well, even though it doesn't mutate state, so policy tests can check exclude_bundle_ids. Screenshot target precedence is rect > window_id > display_id.
- Fake handles: a fixture node's 'id' is used as its handle (with '#2', '#3', … after the window re-opens or the app relaunches); nodes without an id get 'n<counter>'.
- Fixture format extensions: window 'open' (false = defined but opened only by an effect or launch); app 'running'; fake-only node keys id, on_press, options, settable, min, max, step; menu keys separator, toggle, on_select; extra effects close_window, show, hide, select, activate, launch, clipboard. An Apple menu is added automatically if a fixture menu lacks one. Effect references are validated when the fixture loads.

### contract_issues
- CONTRACTS.md should document the optional SnapshotDiff fields (app_before, app_after, window_before, window_after, focus_after_ref). I could not edit docs/ in this scope.
- CONTRACTS.md section 2 says hid_idle_seconds() returns 'a settable attribute' but names neither that attribute nor any other test hook. I chose FakeEngine.hid_idle, .secure_input, .permission_status, .clipboard, set_permissions(), resolve_ref(), secure_value() and events_of(). These should be written into CONTRACTS.md so server and policy test authors use the same names.
- RawNode has no 'focusable' attribute, so 'a focusable text role' in the is_interactive contract can't be evaluated literally. I used 'focused'. If the macOS engine can read AXFocusable cheaply, a RawNode.focusable field (foundation change) would let this match the contract wording.
- CONTRACTS.md doesn't define event names or payloads for FakeEngine.events. The ones in use are: perform_action, press, set_value, focus, insert_text, scroll_to_visible, mouse_move, mouse_click, mouse_drag, scroll, press_key, type_text, app_control, window_control, open, menu_select (with via=menu|shortcut), clipboard_set, notify, screenshot and effect_skipped. Details are JSON-safe; points are written as [x, y].

## system

### deviations
- runner.py uses subprocess.Popen with start_new_session=True and reader/writer threads instead of subprocess.run. subprocess.run cannot kill the whole process group on timeout (required by QUALITY.md A5) and holds unbounded output in memory. The behaviour is otherwise the same as the contract asks: list argv, no shell, partial output on timeout.
- A missing executable returns CommandResult(exit_code=127) and a non-executable one returns 126; they do not raise. A child killed by a signal reports 128+n (the shell convention), so -1 always means a timeout. ensure_success() turns these into NOT_SUPPORTED, TIMEOUT or COMMAND_FAILED for the integration modules.
- Truncation keeps the start of each stream (stdout and stderr separately) and appends '\n[output truncated after N characters; B bytes in total]'. output_records() strips this marker and the partial last record, so parsers only see whole records.
- run_applescript passes the script on stdin (osascript -l AppleScript|JavaScript) instead of with -e, so scripts are not visible in process listings and not limited by ARG_MAX. It also accepts the language aliases 'jxa' and 'js'.
- Optional keyword parameters were added (all have defaults, so existing calls still work): run_applescript(max_output=), spotlight_search(timeout_s=15), list_shortcuts(timeout_s=30), run_shortcut(max_output=), system_info(clock=time.time). New public helpers: ensure_success, output_records, truncate_output, excerpt, output_text, parse_osascript_error, jxa_string, and the argv/script builders.
- sysinfo runs sysctl without -n, so every line is labelled and one unknown key cannot shift the others. It also reads hw.ncpu, kern.boottime and vm.loadavg, and computes uptime_s from kern.boottime instead of parsing the `uptime` command. It adds 'volume' (from osascript 'get volume settings') and an 'unavailable' list naming failed sources.
- set_volume returns the resulting volume settings dict and kill_process returns the signal name ('SIGTERM' or 'SIGKILL'); the contract does not specify return values for either.
- The contract only names the browser functions, so I chose these shapes. Tabs are addressed by TabRef = (window_index, tab_index), both 1-based with window 1 frontmost. Signatures: activate_tab(runner, browser, tab), close_tab(runner, browser, tab=None), open_url(runner, browser, url, *, new_window=False), eval_js(runner, browser, js, tab=None, *, timeout_s=30). The browser argument accepts a key, app name, bundle id or BrowserSpec. frontmost_browser returns a BROWSERS key: the frontmost app if it is a supported browser, otherwise the first running one, otherwise None. BrowserSpec has a tab_select field because Arc switches tabs with `select` instead of `active tab index`. I added Safari Technology Preview to the table.
- list_processes sorts by CPU, then memory, then pid before applying the limit; the contract does not specify an order.
- defaults accepts '-g' and '-globalDomain' as aliases and passes them as NSGlobalDomain. A missing domain or key raises COMMAND_FAILED with details.reason='not_found'.
- Error codes I chose where the contract is silent: unknown shortcut → INVALID_ARGUMENT; kill of a nonexistent pid → INVALID_ARGUMENT; EPERM on kill → COMMAND_FAILED; javascript:/data:/blob:/vbscript: URLs → BLOCKED_BY_POLICY; 'Allow JavaScript from Apple Events' off → NOT_SUPPORTED; osascript -128 → USER_DENIED; -600 or a missing app → APP_NOT_FOUND; assistive-access errors → PERMISSION_ACCESSIBILITY; bad window or tab index (-1728/-1719) in the browser module → INVALID_ARGUMENT.

### contract_issues
- CONTRACTS.md section 5 should record the browser signatures (TabRef tuple, tab=None defaults, new_window flag, what frontmost_browser returns), the added keyword parameters, and the runner's 127/126/128+n exit-code conventions, so the server engineer builds on the same API.
- errors.py has no PROCESS_NOT_FOUND code, so kill_process uses INVALID_ARGUMENT for a pid that does not exist. A dedicated code could be added at the end of the Targets group if agents need to branch on it. Not a blocker.

## macos-engine

### deviations
- MacEngine.__init__ takes one more keyword-only parameter, `runner: CommandRunner | None = None`. It runs osascript (notify), ps (responsible app) and the `open -a` launch fallback, and lets tests pass a FakeRunner. create_engine is unaffected.
- menu_select does not press every level. Like Hammerspoon's selectMenuItem, it walks the AX menu tree with menus closed and presses only the final item. It opens parent menus with AXPress only when a level is empty or the wanted title is missing (lazily filled menus such as Open Recent or History), and cancels any menu it opened (AXCancel, then Escape) on failure. Pressing each level can block AX until menu tracking ends and flashes menus.
- app_at_point does not stop at layer 0. It hit-tests windows of every non-negative layer front-to-back, skipping AXPilot's own windows, alpha-0 windows and raised windows that cover a whole display (click-through overlays). The menu bar strip owned by Window Server (layers 24/25) maps to the frontmost app. Layer-0-only would attribute a click on a deny-listed app's popover or menu-bar item to the app underneath, which is a policy bypass.
- When an AX action, AXValue write or AXSelectedText insert fails with kAXErrorCannotComplete after the full messaging timeout, it is treated as delivered and logged instead of raising TIMEOUT. Apps that open a modal (e.g. pressing Save As…) block the AX reply until the modal closes, and retrying would act twice. Reads still raise TIMEOUT, and a fast CannotComplete on an action raises.
- Installed apps are read from Contents/Info.plist with plistlib rather than NSBundle. The result is the same, it avoids NSBundle's process-lifetime cache, and it is unit-tested on Linux.
- Two modules were added beyond the suggested list: helpers.py (pure logic, imports on any OS) and sync.py (waiting on completion handlers with a deadline).
- The pure-helper tests in tests/engine/test_macos_engine.py are not marked `macos` and run on every OS. Only the MacEngine smoke tests carry @pytest.mark.macos and the darwin + AXPILOT_MACOS_TESTS=1 gate.
- list_windows also returns minimized windows (matched against off-screen CG windows) after the on-screen ones, and includes on-screen windows of accessory (menu-bar) apps. Windows of hidden apps are excluded, as in FakeEngine. Without Accessibility it still lists windows from CGWindowList, with titles that may be empty.
- focus() also brings the owning app to the front and raises the element's window when the app is not frontmost. Keyboard focus is useless in a background app.
- clipboard_get returns no text when the pasteboard is marked org.nspasteboard.ConcealedType (password managers use this marker); the types list still shows the marker.
- mouse_click accepts count 1–3 and raises INVALID_ARGUMENT otherwise. FakeEngine accepts any count ≥ 1.
- Snapshots mark AXMenu nodes without an on-screen frame (closed pop-up and menu-button menus) as invisible, so their items are not offered as clickable.

### contract_issues
- Main run loop: NSWorkspace.runningApplications and NSRunningApplication properties only refresh while the main run loop runs (Apple documents this), and the TIS keyboard-layout functions must run on the main thread on macOS 14+ (they crash the process otherwise). The host runs a run loop, so it is fine. `axpilot stdio --direct` should run the MCP/anyio loop on a worker thread and a Cocoa run loop on the main thread (e.g. PyObjCTools.AppHelper.runConsoleEventLoop()). Without one, the engine falls back: frontmost app via AX, apps that own on-screen windows merged in, pid liveness checks, and the US-ANSI key map after one 0.5 s wait. Please state this in CONTRACTS.md §7 for the host and CLI owners.
- Engine methods have no way to report warnings to the caller, such as an action assumed delivered after a timeout or a fallback keyboard layout. A `warnings` channel, or result objects for perform_action/set_value/insert_text, would let the server surface them as QUALITY A8 asks.
- WindowInfo.window_id has no 'unknown' value. MacEngine uses 0 when a snapshot's root window cannot be paired with a CGWindowID (the only exact mapping is the private _AXUIElementGetWindow). Please document 0 = unknown in models.py and CONTRACTS.md.
- The RawNode.child_count docstring says 'when children was truncated by capture budgets'. MacEngine also sets it for big collections that list only their visible rows (child_count = rows listed + off-screen rows), which perception's collection_rows already handles. The docstring should mention this case.
- The Engine ABC has no way to request permissions for onboarding. MacEngine's package provides axpilot.engine.macos.permissions.request_accessibility() and request_screen_recording(), which do prompt. Either add them to the ABC or have host/ui call these functions directly.
- CONTRACTS.md does not say which window layers app_at_point considers. Please document the hit-test semantics described in the deviations so policy and other engines stay consistent.

## launcher-spikes

### deviations
- `os.getxattr` exists only on Linux in Python. On macOS the S1 probe calls libSystem `getxattr`/`listxattr` through ctypes instead (and uses `os.*xattr` on Linux).
- S5: Accessibility and Screen Recording grants live in the system TCC.db (/Library/Application Support/com.apple.TCC/TCC.db), not the per-user one. `grant_tcc.py` therefore writes both databases by default (`--db both`). The workflow also grants the responsible process found in the baseline probe, because TCC checks that process, not python.
- Launcher additions beyond the spec, all documented in launcher/README.md: (1) the host's stdout/stderr are appended to launcher.log, so startup tracebacks are kept; (2) the host gets AXPILOT_LAUNCHER_VERSION and AXPILOT_LAUNCHER_BUNDLE in its environment; (3) host exit 78 (EX_CONFIG) means "do not restart" and the launcher exits 78; an invalid runtime.json at startup also exits 78; `--runtime` with no value exits 64; (4) if the host is still running 10 s after a forwarded SIGTERM/SIGINT, it gets SIGKILL; when stopping, the launcher exits with the host's status (128+signal if killed); (5) SIGHUP is forwarded only, so a host that dies of it is restarted like after any crash; (6) the launcher honours AXPILOT_HOME and AXPILOT_LOG_DIR, matching axpilot.paths; (7) unknown arguments (e.g. -psn_*) are ignored; (8) a warning is logged when the parent is not launchd; (9) runtime.json is re-read before every restart.
- build.sh additions: an extra BUILDINFO.txt (cdhash per architecture, git commit and dirty state, toolchain); `AXPILOT_LAUNCHER_OUT` to change the output directory; a `PLISTBUDDY` override so tests can stub it; `-swift-version 5 -module-name AXPilot` (the module name is required because the per-architecture output names contain '-'); it prints the cdhash of both slices, not just one.
- Added to the scope's directories: launcher/tests/ (a macOS behaviour suite plus a build-script test that runs anywhere), spikes/tests/ (pytest, Linux-runnable), spikes/spikelib.py (shared helper), S1 install.py and open_from_client.sh, S3 split into strategies.py, hid_idle.py, layout_map.py and plan.example.json, and the S6 framework smoke scripts. These test dirs are not in pyproject testpaths, so they must be run explicitly: `uv run pytest spikes/tests launcher/tests`.
- S3 keyboard layout mapping uses ctypes (Carbon TIS/UCKeyTranslate), as PLAN.md §3 says, so layout_map.py needs no PyObjC. The other S3 scripts and S2/S4 import PyObjC lazily, so their helper functions can be tested on Linux.
